# HAI-MR-05

This repository contains the qualified deterministic HAI MR-05 runtime surface developed from the historical frozen MR-05C-R2 skeleton baseline. The current qualified runtime is not a production or live external-execution system.

Qualified deterministic APIs currently cover discovery, normalization, source acquisition and immutable local capture, frozen MR-03/MR-04 dependency execution, bounded context construction, controller orchestration, evidence persistence, deterministic `Metrics` construction from explicit semantic counters, disclosure qualification, cloud-context admission, cloud-request construction, deterministic cloud-execution authorization binding, cloud-response record construction and transport-binding validation, deterministic cloud-response-to-proposal admission and transport-metadata binding, proposal parsing and identity validation, deterministic verifier qualification plus deterministic public `VerificationRecord` construction from explicit semantic material bound to the exact proposal identity, Human Gate / Human Decision record construction, authoritative Final Result binding, and deterministic top-level workflow composition that integrates cloud-execution authorization, governed admission of an already-obtained immutable external provider response plus non-secret transport metadata into the frozen `CloudResponse`, exact handoff-bound raw-response proposal admission, and transport evidence binding. Qualified deterministic evidence persistence additionally covers create-once/no-replace publication of the pre-final evidence manifest and canonical Final Result to an explicit external evidence root with source-repository isolation. The qualified top-level workflow delegates that final-evidence publication exactly once and exposes the resulting `FinalEvidencePersistenceResult` as an observational record that grants no Human approval, state-transition, source-write, Git, model, or provider authority. The qualified cloud boundary also provides deterministic `CloudExecutionHandoff` construction that binds the exact `CloudRequest` and `CloudExecutionAuthorization` into a read-only handoff identity with `execution_authority = NONE`; it carries no credential material, performs no external I/O, and grants no provider/model execution authority. The qualified top-level workflow constructs that `CloudExecutionHandoff` exactly once from its composed request/authorization pair, exposes it in `WorkflowCompositionResult`, and binds its canonical bytes into the pre-final evidence manifest at `cloud/execution_handoff.json` before admitting the already-obtained external response. The qualified top-level workflow also validates the completed `WorkflowCompositionResult` exactly once through `validate_workflow_composition_result(...)` before returning it, requalifying the request/authorization/handoff/response/proposal chain, exact transport manifest artifacts, Final Result manifest binding, and persisted manifest/final byte identities entirely in memory without adding network, provider, model, auth, Human-decision, state-transition, retry, fallback, filesystem-write, or Git authority. The validator additionally requires the pre-final manifest to bind the exact canonical bytes of the exposed frozen run, cloud context, cloud request, admitted proposal, public verification, and any constructed Human Gate / Human Decision records, closing post-composition artifact-substitution gaps without modifying the frozen evidence or Final Result schemas. The qualified workflow result now also exposes the bounded context, disclosure, Metrics, legacy verifier result, explicit verifier-failure evidence, and explicit terminal-failure evidence used by evidence construction; the top-level validator deterministically reconstructs the complete pre-final evidence manifest and Final Result through the existing evidence builders and requires exact equality, without deriving failure semantics or granting new authority. The qualified cloud boundary also includes one governed adapter that admits an already-obtained immutable external provider response plus non-secret transport metadata into the existing frozen `CloudResponse` only after exact request/authorization/handoff revalidation; the qualified top-level workflow now constructs `CloudExecutionAuthorization` exactly once from the composed `CloudRequest` through `build_cloud_execution_authorization(...)`, using explicit authorized provider/account intent and authorization observational metadata that remain separate from actual transport provider/account/model metadata, then delegates exactly once to the governed external transport adapter before proposal admission. The qualified top-level workflow now also constructs `DisclosureRecord` exactly once through `build_disclosure(...)` from explicit classification, findings, and optional observational metadata before cloud-context admission, without reading sources or granting external authority. It constructs `Metrics` exactly once through `build_metrics(...)` from explicit semantic counters and optional observational metadata, deriving frozen presentation percentages and `metrics_identity` instead of accepting a caller-constructed metrics record. It constructs legacy deterministic `VerifierResult` exactly once through `build_verifier_result(...)` from explicit verifier checks while deriving input, dependency, provenance, Metrics, frozen-contract, decision, reason, and verifier-identity bindings from the qualified composed chain. It constructs public `VerificationRecord` exactly once through `build_verification_record(...)`, binding explicit caller-supplied verification semantics to the exact admitted proposal before adapter qualification without generating findings or choosing a verification result. It constructs `HumanGateRecord` exactly once for Human terminal states through `build_human_gate(...)`, deriving run, task, proposal, verification, package, and context identities plus verification result, reason codes, and verified source references from authoritative composed records together with explicit presentation/evidence material. It then constructs `HumanDecisionRecord` exactly once through `build_human_decision(...)`, binding the record to that exact Human Gate while consuming explicit decision, reason, scope, Human authority reference, and optional observational metadata without choosing the Human decision or granting progression authority. Verified terminal states construct neither a Human Gate nor a Human Decision and reject unsolicited Human construction material. The top-level workflow no longer accepts caller-constructed `CloudExecutionAuthorization`, `CloudResponse`, `disclosure_record`, `metrics_record`, `legacy_verifier_result`, `verification_record`, `human_gate_record`, or `human_decision_record` inputs. This integration executes no external transport, network, provider client, model call, credential handling, retry, fallback, model switch, Human approval execution, autonomous workflow progression, or CLI action.

The frozen package remains `hai_mr05` at `src/hai_mr05/` on branch `hai/mr05-deterministic-workflow-integration`. The repository originated from the MR-05C-R2 skeleton and preserves the exact MR-05A/MR-05B contract references and exact MR-03/MR-04 commit pins. Frozen dependencies remain external and are never copied or vendored.

Implemented qualified APIs and legacy compatibility entrypoints are intentionally distinct. Legacy `not_implemented()` entrypoints remain fail-closed for compatibility and do not represent the implementation status of the qualified APIs. `cli.main()` remains intentionally unavailable and fail-closed.

The current qualified runtime grants no live cloud execution, network authority, provider-client authority, model-call authority, model-routing authority, authentication authority, automatic retry authority, automatic fallback authority, Human approval execution authority, Human Decision side-effect authority, autonomous state-transition authority, or OpenClaw production execution authority. PASS_FOR_REVIEW, Human Gate records, Human Decisions, and Final Result records are governed deterministic records and do not independently grant execution or progression authority.

The Git repository and exact committed runtime remain the source of truth. Documentation and metadata describe the qualified runtime surface but do not grant production readiness, external execution, staging, commit, push, or deployment authority.
